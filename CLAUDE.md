# flipFinder

Python 3.10+ app that finds underpriced Vinted listings and sends Telegram alerts.

## Layout
- `main.py` CLI entry (`--once`, `--dry-run`, `--test-telegram`, `-v`)
- `flipfinder/vinted.py` Vinted search client: loads the `/catalog` page and reads items from its embedded Next.js data (`/api/v2/catalog/items` is gone, 404)
- `flipfinder/analyzer.py` market value (median of comparables matched by query relevance (category words optional, brand counts), brand and model tokens from titles, IQR outlier removal + asking prices over 1.3x the median dropped, bundles (games, 2+ controllers) left out for plain items, same-size preference; "Playstation 5" = ps5, disc/digital are model words, a comparable must share the item's model words except disc), profit, ROI, 1-10 rating, filters (max_price for main deals, default 200; Vinted from abroad skipped unless /abroad on: country from the seller's profile page)
- `flipfinder/scanner.py` per-search scan, price pool cache in `data/pools.json`
- `flipfinder/ebay.py` eBay Browse API client (EBAY_IT, Buy It Now, app token), searched every 20 min, pools every 3 h (~3,050 of 5,000 calls/day), calls/day in `data/ebay.json`
- `flipfinder/subito.py` Subito app JSON API (hades.subito.it, app headers; the website is Akamai-blocked): new listings per category in the home province, kept within `radius_km`, pickup travel cost vs seller shipping
- `flipfinder/sold.py` sold-price tracking: pool history, gone listings checked via item page (`can_buy:false` = sold, 404 = deleted), listing dates from id anchors, adaptive checks per run (halve on 403/429), demand (analyzer.demand, /demand table sent to the Worker every 30 min)
- seller trust: `vinted.parse_item_page` (feedback_count/reputation/badges/last seen) + `parse_profile_page` (/member/<id>: given_item_count = sold), eBay `ebay_seller`; `analyzer.seller_check` skips 0 reviews + 0 sold at ROI >= 100%, warns otherwise; `telegram.seller_lines`
- `flipfinder/storage.py` seen items in `data/seen.json` as `platform:id` (14 day expiry)
- `flipfinder/telegram.py` deal alert text only (the Worker sends)
- `flipfinder/cloud.py` client for the Worker API (FLIPFINDER_API_URL / FLIPFINDER_API_KEY): state (Telegram settings, home area, pool, owned deals), catalog, deals, run report
- `flipfinder/settings.py` Telegram settings and the private home area applied over config.yaml
- `worker/` Cloudflare Worker (JS, D1): shared pot ledger (`src/pot.js`, append-only `ledger` table, /deposit /withdraw /pot /ledger /fix /undo /split; buys are approved by a manager, see team), AI (`src/ai.js`, official @anthropic-ai/sdk, secret ANTHROPIC_API_KEY; settings.ai: enabled off by default, auto on (every deal), hide_no on (❌ NO deals to the Rejected topic once /topic rejected is set: dealTopic, d.rejected, silent, no @mention, ↩️ Not a NO unrej: moves it back + 👍 + d.ai_overruled; not counted in /stats sent, the Mini App list or the digest; off or no topic = muted in their topic), /api/deal waits up to 10 s (AI_HOLD_MS) for the verdict, a slower NO moves the deal (bot.moveDeal: delete + repost), model claude-haiku-5-5 (no temperature: Haiku 5.5 rejects non-default sampling), deep_model claude-sonnet-5-5 (Sonnet calls use beta server-side-fallback-2026-07-01 + fallbacks "default"), daily_cap_eur 0.5, user_daily 20; deals post with the scanner's full text (after the up-to-10 s wait), a slower answer is edited in by ai.apply: "🤖 ✅ YES/❌ NO ..." + "⚠️ risk" at the end (deals.fullText, fitCaption keeps photo captions <= 1024); the AI only returns RISK/IF/RED FLAG/PARTS, ai.finish decides: YES when profit after the part >= min profit (2x for a 🔴 repair), RED FLAG is the only YES->NO override; quick-check answers cached per listing+price (kv ai_cache, 1000); a NO drops the duty ping and reminders, /ai hide-no on deletes it; buttons ✋ Claim/Open, ❓ Seller questions (aq:, Italian to copy), 🧠 Deep analysis (aid:), 👍/👎 (num: 📊 Numbers only for the few short-layout deals, d.short); results cached on the deal (d.ai, d.ai_questions, d.ai_deep); writing rules in SYSTEM; the AI gets the price the message shows (deals.shownPrice), reply-to-deal Q&A thread on the deal (14 days), /ask, @mention, DM photo (downloaded and sent as base64: the file URL holds the bot token), /note /notes /delnote (kv ai_notes, in every system prompt), /ai /aiusage (kv ai_usage, cost from token usage and PRICES), read-only tools get_deal/get_comparables/get_sold_history/get_stock/get_pot/get_schedule, SYSTEM prompt cached and byte-stable, listing data fenced as data (injection test), POST /api/analyze (scanner, only with /ai auto on), POST /api/ai/test (owner test, posts nothing); scanner sends item.photos (4), item.description, comparables (8)), members only (roles are the only key: `team.hasRole`, owner always has one; no role = 🔒 in DMs, silence in the group, 403 `locked` on every Mini App call; /setrole <name> none or /removerole blocks at once and asks the owner about ban+unban; join requests approved only with a role, else declined + owner DM; daily 10:00 member check DMs the owner (Telegram can't list members: checks everyone seen in kv "group_seen"); the cron sets webhook allowed_updates incl. chat_join_request/chat_member), team (`src/team.js`: roles in settings.roles/people, duty/schedule/tasks/health in kv, pinned duty message, 🙋 Request buy -> manager ✅ Approve (replaced the €50 👍 rule), duty pings/escalation in the 5-min cron, active only once a role is set; 2+ can't -> sendPoll with 3 other times; /meeting time|link|off (owner/manager); /minutes -> kv meeting_minutes, Summary topic, next weekly report), reports (`src/reports.js` + `src/xlsx.js`, a no-library .xlsx writer: Sunday 20:00 week and the 1st from 09:00 month before (kv last_monthly), tabs Summary/Deals per day/Buys/Sales/Stock/AI, predicted (d.profit, d.value) vs real profit per category, ↩️ overruled NOs; sent to the owner (sendDocument) + pinned in Summary (kv report_pin), kept in kv reports + report_file:<id> (base64), /reports resends (rep:); suggestions from the AI only with 3+ sales, as checked actions (parseAction: set rule / music rule / value <category|search> ±%), ✅ Apply sug: owner only, once -> settings.rules / settings.music_rules / settings.value_adjust (scanner: rules.value_factor); POST /api/report/test previews), listing kit (`src/kit.js`: on 💸 Bought (repair deals: after the new 🔧 Repaired step, rp:) prices from code (list at market value, floor = paid + part + min profit, quick sale), the AI writes platform/Italian title+description/photos/package (listing kit format in SYSTEM), DM to the seller role (else the buyer) + note in the deal thread; buttons copy_text title/description (kt:/kd: when over 256 chars), 🔄 Rewrite kr:, 🏷 Mark as listed kl: asks the price (pending ask list_price); listed 7 days: ~10% drop never below the floor, DM with 🏷 New price; d.kit in the Mini App Stock tab; POST /api/kit/test previews without saving), Mini App (`public/app/index.html` served as static assets at /app/, API `/app/api/*` in `src/webapp.js`, initData HMAC-checked, actions reuse Bot code via `bot.capture`), Telegram webhook (all commands/buttons, answers in ~1 s), scanner API, 5-min cron (overnight queue, reminders, weekly report), deal tracking, pinned topic intros. Secrets: TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, OWNER_ID, API_KEY, WEBHOOK_SECRET. Tests: `cd worker && npm test` (Node's built-in SQLite stands in for D1). `src/index.js` may only export handlers; logic is in `src/app.js`
- `config.yaml` searches and rules (public: no home area, no ids); secrets in `.env` (FLIPFINDER_API_URL, FLIPFINDER_API_KEY, optional EBAY_CLIENT_ID, EBAY_CLIENT_SECRET); Subito needs no keys (`subito: enabled`, area from the Worker)
- `flipfinder/fastlane.py` + `main.py --fast` + `.github/workflows/fastlane.yml`: fast lane (off by default; Worker settings.fast via /fast: interval 2, per_run 8, groups Guitars/Amps/Pedals/Electronics/Audio; backoff_until after a 403/429 = every 5 min for 1 h + owner DM; kv fast_state {last_started, passes} in /api/state for the too-soon check and rotation; kv fast_stats; POST /api/fast). `Scanner.fast_scan`: first page newest, cached pools only (no rebuilds, no eBay/Subito calls, no sold checks), nothing saved; duplicates prevented by the Worker refusing known deal keys. Triggered every minute by cron-job.org (workflow_dispatch), concurrency group flipfinder-fast. Vinted doesn't block Cloudflare IPs, but catalog pages are ~3.5 MB (too much for the Worker's 10 ms CPU), so the lane runs on Actions
- `.github/workflows/flipfinder.yml` runs `main.py --once` every 5 min (read-only, commits nothing), `data/` (seen items, price pools, run stats) persisted with actions/cache

## Notes
- Keep `request_delay` >= 2s. Handle 401/403 by refreshing the cookie, 429 by backing off.
- Market value: asking prices, blended with likely-sold prices once 3+ sold comparables exist (sold.py). Music searches (Guitars/Amps/Pedals, not budget) need 5 comparables (others 8) and use config `music_rules` (min_profit 20, min_roi 35; max_price, max_roi, min_rating stay the main ones); budget pedals keep budget_rules.
